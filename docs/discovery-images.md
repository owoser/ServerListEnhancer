# 进服前发现与图片配置

## 服务端配置

配置位于 mods/ServerListEnhancer/config/config.json（旧环境可能通过 plugins 映射访问）。首次启动生成默认值，升级保留原配置。示例：

```json
{
  "version": 1,
  "enabled": true,
  "serverId": "my-server",
  "logoId": "default",
  "logoUrl": "",
  "logoData": "",
  "introText": "欢迎来到本服务器\n第二行简介",
  "introImageId": "default",
  "introImageUrl": "",
  "udpProbePort": 0,
  "logLevel": 4
}
```

- Logo 优先级：合法非空 logoData > logoUrl > 内置 default。
- logoData 仅接受规范 data:image/png;base64,...，解码数据 ≤24 KiB；只出现在 HTTP 响应，不进入游戏网络协议。删除该键或置空后重载会取消覆盖。
- 简介图使用 introImageUrl，为空使用内置风景图，大图不要放进状态 JSON。Logo/简介图的 URL 均可指向 PNG、JPEG 或 GIF。
- udpProbePort 默认 0（关闭）。NetherNet 无标准 RakNet ping 时，可显式设置空闲 UDP 端口（如19135），并自行开放防火墙。禁止1024以下端口及19132/19133，不能与游戏端口共用。
- URL 仅 http/https，服务端字段最多512字节；简介最多1024 UTF-8字节；ID仅字母、数字、下划线、连字符，最多64字节。
- 当前客户端真正内置的 ID 是 default。未知 ID 安全回退 default，不能用 ID 传任意路径。
- serverId 用于诊断，不是客户端缓存归属，建议使用英文稳定 ID。
- 修改后执行 /sle reload，立即发布不可变 HTTP 快照；客户端按自身刷新周期重新拉取，玩家进服与否不影响图文获取。
- enabled:false 显式撤销远程图文，不破坏原生状态响应。
- **不支持服务端热卸载。配置重载不等于 DLL 升级，更新必须停止并重启服务器。**

## HTTP 响应

复用原生 NetherNet GET /v1/join，不另开 SLE 专用服务。保留正常名称、人数、游戏版本、协议等原生字段，追加：

```json
{
  "server_list_enhancer": {
    "schemaVersion": 1,
    "revision": "内容变更标识",
    "enabled": true,
    "cacheTtlSeconds": 300,
    "serverId": "my-server",
    "logo": {"type":"builtin", "value":"default"},
    "introText":"欢迎来到本服务器",
    "introImage": {"type":"url", "value":"https://example.com/banner.gif"},
    "udpProbe": {"protocol":"sle-echo-v1", "port":19135}
  }
}
```

客户端只认 schemaVersion=1；未知/错误扩展不破坏基础状态。Logo 支持 builtin/url/data，简介图建议 builtin/url。revision 是变更标识，不是签名或身份认证。

```powershell
curl.exe --noproxy "*" http://127.0.0.1:19132/v1/join
```

前提是原生 HTTP 信令监听存在并且可达。游戏 UDP 可达不等于 HTTP TCP 可达；远程玩家不能使用自己的127.0.0.1访问你的服务器。纯 RakNet 或没有 HTTP 的服务器显示默认或旧缓存。

## 客户端行为

- 自有服务器条目独立管理，不读写原版列表，手动配置图文优先于发现资料。
- 启动自动排队查全部条目，4个状态工作线程，超过4台排队不丢弃。打开列表按新鲜度补查；添加/编辑保存立即探测；手动刷新绕过新鲜度并合并同端点在途请求。
- 状态通常60秒节流，视觉TTL默认300秒；请求总预算4秒，完整JSON最多64 KiB，分块响应亦在追加前检查。
- 实际端点和请求代际决定归属，同名或相同serverId不互相覆盖；编辑/删除后拒绝旧结果。
- cache/discovery.json 保存预发现资料；cache/images 保存规范PNG、受限GIF原文件及引用映射。已有图片立即复用，不等网络刷新结束；下次启动可重建被删除的默认图片缓存。
- 失败保留旧图文并标记失败；明确enabled:false清除远程图文，无历史图片立即用内置默认图。

## 图片规格与预算

**2 MiB 是每一张图片的完整下载文件上限。** Logo 与简介图独立计算，不是二者合计；因此同一服务器两张都达到上限时，输入文件合计最多4 MiB。GIF 按整个文件计算，不是每帧2 MiB。内存、GPU像素和磁盘缓存另有下表的全局预算，不能把压缩文件大小当成运行内存大小。

| 项目 | Logo | 简介图 | 约束范围 |
| --- | --- | --- | --- |
| 内置默认图 | 64×64 PNG | 960×320 PNG | 原创，字节编入DLL |
| 建议静态源图 | 方形64–512像素 | 约3:1，960×320 | 推荐值，不是强制比例 |
| 单文件下载 | ≤2 MiB | ≤2 MiB | 分别计算，含整个GIF |
| PNG/JPEG输入 | 边长≤4096，总像素≤4,000,000 | 同左 | 每张图 |
| 静态归一化输出 | ≤512×512 | ≤1600×900 | 等比缩放，不放大 |
| GIF逻辑画布 | ≤1024×1024 | ≤1024×1024 | 每个GIF |
| GIF帧数/单轮时长 | ≤120帧 / ≤30秒 | 同左 | 不是播放总寿命，允许无限循环 |
| GIF输出包围盒 | ≤256×256 | ≤640×360 | 按帧数/预算继续缩小，保持比例 |
| GIF解码预算 | ≤16 MiB | ≤16 MiB | 每动画，包含合成工作画布预算 |
| GIF CPU总预算 | 64 MiB | 共用 | 所有存活解码动画 |
| GIF GPU像素预算 | 32 MiB、最多8张活动纹理 | 共用 | 本模组动画纹理的RGBA像素量，不是驱动总显存 |
| 图片磁盘缓存 | 128 MiB | 共用 | 静态/动态/引用映射共用 |
| 内联data图片 | PNG解码后≤24 KiB | 不建议内联 | 不是24 KiB的base64文本；编码约32 KiB |

- 图片2个工作线程，单任务总预算10秒，失败冷却5分钟。完整状态JSON另限64 KiB。原始压缩文件上限与解码预算同时生效。
- GIF使用WIC解码，自行完成局部帧、透明、disposal=2/3、局部调色板和循环合成；小于20ms的帧延迟归一为100ms。一次有界解码全部帧，不是流式播放器。
- 不满足动画帧数/画布/内存预算时，尝试在静态尺寸限制内显示首帧；损坏、超文件上限或静态解码也失败则用旧缓存/默认图片。首帧回退不保证动画局部帧恢复为完整场景。
- 只为可见列表请求图片；离开列表/进入弹窗后释放动画引用与自有GPU纹理，未再使用的动画和纹理分别按3秒/2秒淘汰。渲染回调不下载、不解码。
- 128 MiB为缓存清理目标：保护默认图及本次写入文件，后台删除旧哈希文件；不承诺限制游戏自身静态纹理缓存或驱动额外分配。
- 仅HTTP(S)，拒绝URL凭据与重定向，HTTPS严格验证证书；外部不能指定本地路径。不支持SVG、WebP。

## 地址与输入校验

- 接受IPv4、带方括号的IPv6、完整ASCII域名（或Punycode）与localhost；未填端口默认19132。仅去除两端空白，不悄悄截掉非法字符。
- 端口必须全为数字且在1–65535；IPv4必须四段0–255、不接受含混的前导零；域名标签1–63字符、不能以下划线或连字符边界命名。
- 拒绝协议前缀、路径、内部空格、用户凭据、单段普通主机名、残缺IPv4/IPv6和重复端口。历史非法记录保留并提示编辑，不发送网络探测。
- 保存按钮、Enter和底层存储使用同一个校验器。语法合法不证明域名存在、端口开放或对方确为Minecraft；DNS/连接失败属于下一阶段状态，不能靠语法校验保证。
- 输入框支持UTF-8字符边界移动/删除、Home/End、Shift选区、Ctrl+A/C/X/V、Tab切换和500ms光标闪烁；Alt/Win组合键不输入字符。支持粘贴中文，尚无完整IME组合输入。

## 真实UDP延迟

- 标准RakNet服务器：在游戏UDP端口发送unconnected ping，校验pong的随机标识和magic；不需要服务端安装SLE。
- 开启udpProbePort的SLE服务器：从HTTP扩展发现端口，发32字节随机nonce回显包，服务端等长响应，不做流量放大。每IP每秒10包、全局每秒200包、最多256个来源计数。
- 每次3个样本取中位数，DNS耗时不计入RTT；DNS预算1.5秒，每个UDP样本最多1.5秒。2个工作线程，结果缓存15秒。隐藏列表时清除待测队列，停止时取消等待并回收线程。
- ≤60ms绿色，61–100ms黄色，>100ms红色；1000ms以上也可实际测得。无响应/DNS失败显示灰色，不伪造0ms，也不等同于服务器离线。版本取HTTP原始version字段，不由延迟猜测。

## TLS边界

当前客户端显式启用旧NetherNet元数据的自签证书兼容策略，并在特定连接/信道失败时回落同端点HTTP；**这不提供服务器身份认证**。状态资料应视为不可信输入，不承载秘密。不要将该策略用于其它HTTPS业务。

图片下载独立使用严格证书策略，不沿用元数据的证书忽略设置。明文HTTP不防中间人；重要部署建议使用可信TLS端点。
